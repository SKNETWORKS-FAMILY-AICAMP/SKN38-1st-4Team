# 위험지수 — 자료, 계산, 등급

처음 출처는 팀 노션 「프론트엔드 기획」의 「데이터 / 분석 기준」 시안(`plan-images/data-criteria-draft.jpg`)과 탐색 화면 시안입니다. 팀 분석 결과 자료(2026-11-09 계산)를 받은 뒤, 계산과 지역을 그 자료에 맞게 고쳤습니다. 가중치와 등급 경계는 팀이 정한 값입니다(2026-11-10).

## 데이터 기준

- 기준 연도: 2025년
- 분석 대상 지역: 서울특별시 5개 자치구 — 강북구, 강서구, 도봉구, 서대문구, 은평구. 팀이 강수 자료를 이 5개 구로 줄여 분석했으므로 앱에도 이 5개 구의 주차장만 넣습니다.
- 분석 단위: 개별 주차장(163곳)

| 자료 | 내용 | 출처 |
|---|---|---|

| 지형·고도 | 지형의 높낮이, 경사도 등 지형적 특성 | 국토지리정보원 |

| 주차장 | 주차장 위치 등 기본 정보 | 서울특별시 공영주차장 등 |

팀 확인 필요: 실제로 쓴 원본 데이터셋 이름, 받는 곳(링크), 받은 날짜를 이 표에 더해야 합니다.

팀이 원본 자료를 가공해 만든 표입니다. 받은 그대로 둡니다(UTF-8, BOM 있음).

| `parking_risk_result.csv` | 주차장별 침수 이력·강수·지형 점수(0\~100), 종합 점수, 등급, 순위 | 806 |

| `flood_area.csv` | 침수 지점 주소, 위도·경도, 침수 깊이 점수(0.2·0.3·0.6·1.0) | 1,132 |

- `parking_risk_result.csv` 의 종합 점수, 등급, 순위는 쓰지 않습니다. 앱이 아래 가중치와 등급 경계로 다시 계산합니다.

## 분석 과정

1. 데이터 수집 — 공공데이터와 오픈 API
2. 데이터 전처리 — 결측치 처리, 좌표 매칭 등
3. 지표 표준화 — 지표마다 단위가 다르므로 0~1 범위로 맞춤
4. 가중치 적용 — 지표별 중요도 반영
5. 위험지수 산출 — 주차장별 상대적 위험도(0~100)

## 지표별 세부 기준

받은 자료의 값으로 거꾸로 확인한 계산입니다(소수 둘째 자리 반올림 차이 안에서 모든 행이 맞음). 세 점수는 0\~100 이고, 앱 입력 자료에는 100 으로 나눠 넣습니다.

- 강수량 위험(자치구 단위, 같은 구의 주차장은 점수가 같음)
  `0.4 × 최대 1시간 강수량(mm) + 0.4 × 최대 3시간 강수량(mm) + 0.2 × 호우일수`
- 침수 이력 위험(시안 이름 「침수사고 위험」): 주차장에서 가장 가까운 침수 지점이 1km 안에 있으면
  `40 × (1 − 거리(m) ÷ 1000) + 60 × 침수 깊이 점수`, 1km 안에 없으면 0점. 거리는 위도·경도로 잰 구면 직선거리입니다.
- 지형(고도) 위험: 저지대 점수(`parking_lowland.csv`)를 그대로 씁니다.

상세 비교 화면에서는 「침수 대표지점까지의 거리」와 「침수구역 중첩 여부」를 따로 보여 주지 않습니다. 계산에 쓰는 것은 막지 않습니다.

팀 확인 필요:

- 저지대 점수를 어떻게 계산했는지(쓴 고도 자료, 기준)가 자료에 없습니다.
- 강수량 점수는 mm 를 그대로 더한 값이라 100 을 넘을 수 있습니다. 지금 5개 구는 39.2점부터 91.0점까지라 문제가 없지만, 지역이나 연도를 바꾸면 표준화 방법을 정해야 합니다. 100 을 넘으면 앱 입력 자료 검사에서 오류가 납니다.

## 계산식

```text
침수 위험도 지수 = 100 × (α × 강수량 위험 + β × 침수 이력 위험 + γ × 지형(고도) 위험)
```

- 세 위험 값은 0~1 로 표준화한 값이고, α + β + γ = 1 이므로 결과는 0~100 입니다.
- 화면에는 정수 점수(예: 33점)로 보여 줍니다. 반올림은 한 함수에서만 합니다.

| 지표 | 기호 | 가중치 |
|---|---|---|
| 강수량 위험 | α | 0.30 |
| 침수 이력 위험 | β | 0.45 |
| 지형(고도) 위험 | γ | 0.25 |

팀이 정한 값입니다(2026-11-10). 시안의 예시값(0.45 / 0.35 / 0.20)은 쓰지 않습니다.

## 등급

| 등급 | 점수 |
|---|---|
| 상대적 낮음 | 0~39 |
| 보통 | 40~69 |
| 상대적 높음 | 70~100 |

최신 시안(`search-nearby-tab.jpg`) 기준이며, 팀이 이 3단계를 쓰기로 했습니다(2026-11-10). 예전 시안(`dashboard-draft.jpg`, `search-draft-b.jpg`)은 0~33 / 34~66 / 67~100 을 썼으나 최신 것을 따릅니다. 받은 자료의 4단계 등급(20점 간격, 「매우 낮음」 포함)도 쓰지 않습니다. 등급 색은 `product-plan.md` 「색」에 있습니다.

5개 구 163곳을 위 가중치로 계산하면 상대적 낮음 29곳, 보통 123곳, 상대적 높음 11곳입니다.

## 안내 문구

시안에 있는 문구입니다. 화면에 넣을 때 그대로 쓰거나 뜻을 바꾸지 않는 선에서 줄입니다.

- 지도·위험지수 옆에 항상: 「2025년 데이터 기반 상대적 위험도 · 실시간 침수 예측 아님」
- 위험지수 설명: 「위험지수는 상대적 위험 수준(0~100)을 의미하며, 실제 침수 발생을 보장하지 않습니다.」
- 분석 결과 해석 시 유의사항(데이터 / 분석 기준 시안)
  - 본 위험지수는 실제 침수 발생 확률이 아닌, 분석 대상 내 상대적 위험 수준을 나타냅니다.
  - 사용한 데이터의 해상도와 시점에 따라 실제 현장 상황과 차이가 있을 수 있습니다.
  - 실시간 강수 상황은 반영하지 않으므로, 집중호우 시에는 기상특보 및 현장 안내를 함께 확인해 주세요.
- 비교 화면 유의사항(상세 비교 시안)
  - 본 서비스는 과거 데이터 기반의 상대적 위험도 비교 결과입니다.
  - 실제 침수는 실시간 강수, 배수 상황, 현장 여건 등에 따라 달라질 수 있습니다.
  - 집중호우 시에는 관할 기관의 기상특보와 현장 안내를 함께 확인해 주세요.

## 앱 입력 자료

분석 결과는 앱이 읽는 파일 하나로 넘깁니다. 형식을 바꾸려면 이 표를 먼저 고친 뒤 코드를 맞춥니다.

파일: `data/parking_risk.csv` (UTF-8, 엑셀에서 한글이 깨지지 않게 BOM 을 붙임, 한 줄에 주차장 하나, 지금 163곳)

| 열 | 뜻 | 값 | 받은 자료의 열 |
|---|---|---|---|
| `parking_id` | 주차장 고유 번호 | 문자열, 겹치지 않음 | `parking_lot_id` |
| `name` | 주차장 이름 | 문자열 | `parking_name` |
| `address` | 주소 | 문자열 | `address` |
| `lat` | 위도 | WGS84 십진수 | `latitude` |
| `lon` | 경도 | WGS84 십진수 | `longitude` |
| `rain_risk` | 강수량 위험 | 0\~1 | `rainfall_risk_score` ÷ 100 |
| `terrain_risk` | 지형(고도) 위험 | 0\~1 | `lowland_risk_score` ÷ 100 |
| `flood_history_risk` | 침수 이력 위험 | 0\~1 | `flood_risk_score` ÷ 100 |

- 만들기: `python -m analysis.build_parking_risk` (`data/raw/` 를 읽어 이 파일을 다시 씁니다). `data/raw/` 를 바꾸면 이 명령을 다시 돌려 함께 커밋합니다. 둘이 어긋나면 테스트가 실패합니다.
- 읽기·검사: `core/parking.py` 의 `load()`. 열이 빠졌거나, 빈 값·겹치는 번호가 있거나, 위험 값이 0\~1 을 벗어나거나, 좌표가 서울 범위를 벗어나면 오류를 냅니다.
- 위험지수와 등급은 앱(`core/risk.py`)이 이 세 값과 가중치로 계산합니다. 가중치를 바꿔도 자료를 다시 만들 필요가 없게 하기 위해서입니다.
- 사용자 위치와 주차장 사이 거리는 위도·경도로 하버사인 공식(구면 위 직선거리)을 써서 계산합니다. 길 찾기 거리가 아닙니다.
